# SKB Knowledge Continuity Contract

This repository participates in Sobuj's canonical knowledge-continuity system: `soobujmiah/skb`.

## Session start

For substantive work, first follow the repository's own instructions. Then consult the relevant SKB context through its canonical navigation before making project-level decisions. Use only the minimum relevant context; do not blindly copy SKB content into this repository.

Repository-local evidence, direct source evidence, and explicit human decisions remain authoritative for this repository. SKB provides durable context and continuity; it does not silently override repository rules or human authority.

## Adaptive work

Do not assume a fixed language, framework, architecture, documentation structure, or implementation pattern. Select the structure, technology, documentation, tests, and validation appropriate to the actual task and constraints. Reuse proven conventions where they fit, but do not copy unrelated project structure merely for consistency.

## Knowledge return

At the end of substantive work, review whether durable project facts, decisions, constraints, failures, important discoveries, or evidence should be returned to SKB. Return only supported, useful knowledge. Do not return secrets, credentials, private payloads, routine noise, or unsupported claims.

## Fresh-agent continuity

A future agent should be able to discover this contract from this repository without relying on prior conversation memory. If SKB is unavailable, do not invent missing context; continue only from verified repository evidence when safe and record the limitation.

## Scope

This contract concerns knowledge continuity only. It does not authorize commits, pushes, releases, deployments, credential changes, or other external mutations.
